# FotoArchief v0.9.51

## Nederlands

### Wijzigingen in deze versie

- Dertig voorzieningen in zes batches: opgeslagen AI-resultaten bij foto's, gepagineerde historie, taaklinks en veilige beoordeling zonder automatische metadatawijziging.
- Hercontrole van actuele toestemming, budget en noodstop in de worker; voortgang blijft behouden bij annulering halverwege een chunk.
- Opslagmigratieretries, versleutelde tweede back-up, upgrade-/providercontractproeven, kleine echte binaire ingestproef, relevantie-evaluatie, privacyregressies en uitgebreide Nederlandse lokalisatie.

### Operatoracties
Geen wijzigingen aan Compose-mappings of `.env.example` voor bestaand gedrag. Tweede back-up is opt-in via een privaat configuratiebestand met `BACKUP_PARENT_DIR`, `ENCRYPTED_COPY_DIR`, `KEY_FILE`, `LOCK_DIR` en `RETENTION_POLICY`; zet `FOTOARCHIEF_SECOND_BACKUP_ENABLED` pas na configuratie op true (standaard false). Retentie wordt geregistreerd, niet automatisch afgedwongen. Laat `FOTOARCHIEF_SKIP_IMAGE_PULL=0` bij normale upgrades; 1 is alleen voor vooraf geladen/geteste images. Deze versie gebruikt nog `database_json`; een pgvector-extensieproef is geen applicatieadapter. Live providers, offsite-herstel en representatieve schaal/relevantie blijven afzonderlijke acceptatie.

### Bewijs en grenzen
Deze toelichting is achteraf gebaseerd op de commits van deze tag en de gekoppelde PR's; er zijn voor deze aanvulling geen oude tests opnieuw uitgevoerd. Dit blijft een testrelease, geen productiecertificering. Bron: [helmerzNL/FotoArchief#17](https://github.com/helmerzNL/FotoArchief/pull/17). [Code van deze release / vergelijking](https://github.com/helmerzNL/FotoArchief/compare/v0.9.50...v0.9.51).

## English

### Changes in this version

- Thirty facilities in six batches: stored AI results on photos, paginated history, job links and safe review without automatic metadata changes.
- Worker rechecks current consent, budget and emergency stop; progress is preserved when cancelling mid-chunk.
- Storage-migration retries, encrypted second backup, upgrade/provider-contract checks, a small actual binary-ingest test, relevance evaluation, privacy regressions and expanded Dutch localization.

### Operator actions
No Compose-mapping or `.env.example` changes for existing behavior. Second backup is opt-in through private configuration containing `BACKUP_PARENT_DIR`, `ENCRYPTED_COPY_DIR`, `KEY_FILE`, `LOCK_DIR` and `RETENTION_POLICY`; set `FOTOARCHIEF_SECOND_BACKUP_ENABLED` to true only after configuration (default false). Retention is recorded, not automatically enforced. Leave `FOTOARCHIEF_SKIP_IMAGE_PULL=0` for normal upgrades; 1 is only for preloaded/tested images. This version still uses `database_json`; a pgvector-extension check is not an application adapter. Live providers, offsite restore and representative scale/relevance remain separate acceptance work.

### Evidence and limitations
This retrospective description is based on this tag's commits and the linked PRs; historical tests were not rerun for this update. This remains a test release, not production certification. ## English

Test release containing readable PHP with locked production dependencies,
a Compose deployment archive and the Docker image accepted by this
workflow. This is not a production-readiness certification.

Download IMAGE.txt and IMAGE-DIGEST.txt for the immutable version tag and
digest. IMAGE-LATEST.txt references the rolling :latest tag, which is
updated to the same image by every successful highest SemVer release. Prefer
the version tag or digest for reproducible deployments. Alternatively,
load fotoarchief-docker.tar.gz with docker load and use the APP_IMAGE value
from IMAGE-LOCAL.txt; no registry credentials are required. The PHP host
requires PHP 8.5, PostgreSQL, the required extensions and cron/workers.
Set its document root to public/. Composer is not needed on the host.

Operator changes: set APP_IMAGE to the supplied tag or digest. Keep
DB_PASSWORD unchanged for existing volumes. Preserve app-storage and
postgres-data. The HTTP mapping remains
${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080. Packaging
introduces no new mandatory environment variables. Before upgrading,
create a verified backup and consult the operational documentation.
The application file limit is 104857600 bytes; every proxy must allow at
least 115343360 bytes per request and the configured request duration of
300 seconds.
