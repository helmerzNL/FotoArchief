Probeer de mislukte AI-taak daarna handmatig opnieuw. Historische taken starten niet automatisch; bestaande queued taken volgen hun normale retrybeleid.
- De specifieke productie-installatie en het bestaan van de gemelde foto zijn niet rechtstreeks gecontroleerd.

## English

### AI photo-reference fix
- Image analysis and embedding indexing accept full FA photo numbers and internal IDs. The whole batch is validated for existence and access before dispatch; duplicate references count once. Invalid input starts no job.
- Retry repairs old failed AI jobs containing photo numbers, preserves audit history, and records conversion to internal IDs. Already converted IDs are never reinterpreted as photo numbers.
- This fixes incorrect photo lookup before scanning or provider contact. ClamAV and provider safety remain unchanged.
- Validation: 516 local tests passed, 12 optional tests skipped; PHPStan, Pint, and translation checks passed. CI for PHP 8.5, PostgreSQL fresh/forward, container acceptance, and production archives passed.
- Upgrade: no new database migrations, environment variables, Compose mappings, or changed limits. Pull the image and recreate the web, worker, and scheduler containers. Then retry the failed AI job manually. Historical jobs do not start automatically; existing queued jobs follow their normal retry policy.
- The specific production installation and existence of the reported photo were not directly checked.

### Packages and general installation

Test release containing readable PHP with locked production dependencies,
a Compose deployment archive and the Docker image accepted by this
workflow. This is not a production-readiness certification.

Download IMAGE.txt and IMAGE-DIGEST.txt for the immutable version tag and
digest. IMAGE-LATEST.txt references the rolling :latest tag, which is
updated to the same image by every successful highest SemVer release. Prefer
the version tag or digest for reproducible deployments. Alternatively,
load fotoarchief-docker.tar.gz with docker load and use the APP_IMAGE value
from IMAGE-LOCAL.txt; no registry credentials are required. The PHP host
requires PHP 8.5, PostgreSQL, the required extensions and cron/workers.
Set its document root to public/. Composer is not needed on the host.

Operator changes: set APP_IMAGE to the supplied tag or digest. Keep
DB_PASSWORD unchanged for existing volumes. Preserve app-storage and
postgres-data. The HTTP mapping remains
${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080. Packaging
introduces no new mandatory environment variables. Before upgrading,
create a verified backup and consult the operational documentation.
The application file limit is 104857600 bytes; every proxy must allow at
least 115343360 bytes per request and the configured request duration of
300 seconds.
