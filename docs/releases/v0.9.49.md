# FotoArchief v0.9.49

## Nederlands

### Wijzigingen in deze versie

- Taken met nul verwerkte en mislukte items worden niet meer ten onrechte als voltooid opgeslagen.
- Persistent auditlog per AI-item en queuepoging, met de laatste tien gebeurtenissen op de taakpagina; geen API-sleutels, beeldbytes of providerresponses in de auditcontext.
- Forward migration corrigeert oudere inconsistente runs; een retry van een legacy AI-run begint bij het eerste item met schone tellers.

### Operatoracties
Geen nieuwe omgevingsvariabelen of Compose-mappings. Laat de automatische migratie `operation_run_audit_events` aanmaken, zorg dat app, worker en scheduler dezelfde nieuwe versie draaien en probeer daarna de mislukte taak opnieuw.

### Bewijs en grenzen
Deze toelichting is achteraf gebaseerd op de commits van deze tag en de gekoppelde PR's; er zijn voor deze aanvulling geen oude tests opnieuw uitgevoerd. Dit blijft een testrelease, geen productiecertificering. Bron: [helmerzNL/FotoArchief#12](https://github.com/helmerzNL/FotoArchief/pull/12). [Code van deze release / vergelijking](https://github.com/helmerzNL/FotoArchief/compare/v0.9.48...v0.9.49).

## English

### Changes in this version

- Jobs with zero processed items and failed items are no longer incorrectly stored as completed.
- Persistent audit log per AI item and queue attempt, showing the ten latest events on the job page; no API keys, image bytes or provider responses in audit context.
- A forward migration corrects older inconsistent runs; retries of legacy AI runs restart at the first item with clean counters.

### Operator actions
No new environment variables or Compose mappings. Allow the automatic migration to create `operation_run_audit_events`, ensure app, worker and scheduler run the same new version, then retry the failed job.

### Evidence and limitations
This retrospective description is based on this tag's commits and the linked PRs; historical tests were not rerun for this update. This remains a test release, not production certification. Source: [helmerzNL/FotoArchief#12](https://github.com/helmerzNL/FotoArchief/pull/12). [Release code / comparison](https://github.com/helmerzNL/FotoArchief/compare/v0.9.48...v0.9.49).

## English

Test release containing readable PHP with locked production dependencies,
a Compose deployment archive and the Docker image accepted by this
workflow. This is not a production-readiness certification.

Download IMAGE.txt and IMAGE-DIGEST.txt for the immutable version tag and
digest. IMAGE-LATEST.txt references the rolling :latest tag, which is
updated to the same image by every successful highest SemVer release. Prefer
the version tag or digest for reproducible deployments. Alternatively,
load fotoarchief-docker.tar.gz with docker load and use the APP_IMAGE value
from IMAGE-LOCAL.txt; no registry credentials are required. The PHP host
requires PHP 8.5, PostgreSQL, the required extensions and cron/workers.
Set its document root to public/. Composer is not needed on the host.

Operator changes: set APP_IMAGE to the supplied tag or digest. Keep
DB_PASSWORD unchanged for existing volumes. Preserve app-storage and
postgres-data. The HTTP mapping remains
${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080. Packaging
introduces no new mandatory environment variables. Before upgrading,
create a verified backup and consult the operational documentation.
The application file limit is 104857600 bytes; every proxy must allow at
least 115343360 bytes per request and the configured request duration of
300 seconds.
