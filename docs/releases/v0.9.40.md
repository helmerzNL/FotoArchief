# FotoArchief v0.9.40

## Nederlands

### Wijzigingen in deze versie

- Native adapters voor OpenAI, Anthropic, Gemini en OpenRouter, met providerkeuze per AI-functie en zonder stille terugval.
- Afzonderlijke configuratie voor beeldanalyse en multimodale embeddings, maandbudgetreserveringen, annulering en afgeschermde providerfouten.
- Toestemming per bezoeker voordat een externe provider een publieke semantische zoekvraag ontvangt; gewone publieke zoekopdrachten blijven beschikbaar zonder die toestemming.

### Operatoracties
Providers staan standaard uit met een maandbudget van 0 cent. Voeg alleen voor activering de toepasselijke private `AI_OPENAI_*`, `AI_ANTHROPIC_*`, `AI_GEMINI_*` of `AI_OPENROUTER_*` waarden uit de template van deze versie toe: API-sleutel, enabled-status, model, kosten en positief maandbudget. Herstart app, worker en scheduler na configuratiewijziging. Deze release gebruikte nog omgevingsconfiguratie; databasebeheer van providers volgt pas in v0.9.43. Er is geen live of betaald providerverkeer bewezen door de adaptertests.

### Bewijs en grenzen
Deze toelichting is achteraf gebaseerd op de commits van deze tag en de gekoppelde PR's; er zijn voor deze aanvulling geen oude tests opnieuw uitgevoerd. Dit blijft een testrelease, geen productiecertificering. Bron: [helmerzNL/FotoArchief#3](https://github.com/helmerzNL/FotoArchief/pull/3). ## English

### Changes in this version

- Native adapters for OpenAI, Anthropic, Gemini and OpenRouter, with capability-specific provider selection and no silent fallback.
- Separate image-analysis and multimodal-embedding configuration, monthly budget reservations, cancellation and redacted provider errors.
- Per-visitor consent before an external provider receives a public semantic-search query; ordinary public search remains available without that consent.

### Operator actions
Providers default to disabled with a monthly budget of 0 cents. Only when enabling a provider, add the applicable private `AI_OPENAI_*`, `AI_ANTHROPIC_*`, `AI_GEMINI_*` or `AI_OPENROUTER_*` values from this version's template: API key, enabled state, model, costs and a positive monthly budget. Restart app, worker and scheduler after configuration changes. This release still used environment configuration; database-managed providers arrive in v0.9.43. Adapter tests do not establish live or paid provider acceptance.

### Evidence and limitations
This retrospective description is based on this tag's commits and the linked PRs; historical tests were not rerun for this update. This remains a test release, not production certification. Test release: readable PHP with locked production dependencies, Compose
deployment archive and the Docker image accepted by this workflow.

Download IMAGE.txt/IMAGE-DIGEST.txt for the registry tag and immutable digest.

The PHP host needs PHP 8.5, PostgreSQL, required extensions and cron/workers;
set its document root to public/. Composer is not needed on the host.

Operator changes: set APP_IMAGE to the supplied tag/digest. Keep DB_PASSWORD
unchanged for existing volumes. Preserve app-storage and postgres-data.
The HTTP mapping remains ${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080.
No new mandatory environment variables are introduced by packaging.
Before upgrading, create a verified backup and consult the operational docs.
The application file limit is 104857600 bytes; any proxy must allow at least
115343360 bytes per request and the configured 300-second request duration.
