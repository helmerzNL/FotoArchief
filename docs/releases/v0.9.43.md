# FotoArchief v0.9.43

## Nederlands

### Wijzigingen in deze versie

- Bundelt de wijzigingen sinds v0.9.40, inclusief de niet afzonderlijk getagde tussenversies: tweetalige package-/release-informatie en Nederlandse interfacecatalogi.
- Coördineert forward-only PostgreSQL-migraties vóór app, worker en scheduler starten, met advisory lock, expliciete status en begrensde wachttijd.
- Beheert externe/native AI-providers vanuit PostgreSQL; credentials zijn met `APP_KEY` versleuteld, providerwijzigingen worden zonder secrets geaudit en custom endpoints zijn begrensd tot publieke HTTPS-hosts.

### Operatoracties
Behoud dezelfde `APP_KEY`. Bij eerste creatie van de providertabel worden ondersteunde legacy AI-omgevingswaarden eenmalig geïmporteerd; controleer daarna ieder record in AI-instellingen en test de verbinding voordat legacywaarden worden verwijderd. Behoud `AI_LOCAL_ENDPOINT` voor de lokale provider. Defaults zijn `APP_LOCALE=nl`, `APP_FALLBACK_LOCALE=nl` en `DEPLOYMENT_MIGRATION_LOCK_TIMEOUT_SECONDS=300`; expliciet beheerde omgevingen nemen deze waarden over voor app, worker en scheduler. Raadpleeg de gekoppelde migratiebeschrijvingen voor de exacte legacyvariabelen en Compose-mappings.

## English

### Changes in this version

- Includes changes since v0.9.40, including intermediate versions without separate tags: bilingual package/release information and Dutch UI catalogues.
- Coordinates forward-only PostgreSQL migrations before app, worker and scheduler start, with an advisory lock, explicit status and bounded waiting.
- Manages external/native AI providers in PostgreSQL; credentials are encrypted with `APP_KEY`, provider changes are audited without secrets and custom endpoints are restricted to public HTTPS hosts.

### Operator actions
Preserve the same `APP_KEY`. Supported legacy AI environment values are imported once when the provider table is first created; inspect each record in AI settings and test connectivity before removing legacy values. Retain `AI_LOCAL_ENDPOINT` for the local provider. Defaults are `APP_LOCALE=nl`, `APP_FALLBACK_LOCALE=nl` and `DEPLOYMENT_MIGRATION_LOCK_TIMEOUT_SECONDS=300`; explicitly managed environments carry these values into app, worker and scheduler. Consult the linked migration descriptions for exact legacy variables and Compose mappings.

## English

Test release containing readable PHP with locked production dependencies,
a Compose deployment archive and the Docker image accepted by this
workflow. This is not a production-readiness certification.

Download IMAGE.txt and IMAGE-DIGEST.txt for the registry tag and immutable
digest. Alternatively, load fotoarchief-docker.tar.gz with docker load and
use the APP_IMAGE value from IMAGE-LOCAL.txt; no registry credentials are
required. The PHP host requires PHP 8.5, PostgreSQL, the required extensions
and cron/workers. Set its document root to public/. Composer is not needed
on the host.

Operator changes: set APP_IMAGE to the supplied tag or digest. Keep
DB_PASSWORD unchanged for existing volumes. Preserve app-storage and
postgres-data. The HTTP mapping remains
${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080. Packaging
introduces no new mandatory environment variables. Before upgrading,
create a verified backup and consult the operational documentation.
The application file limit is 104857600 bytes; every proxy must allow at
least 115343360 bytes per request and the configured request duration of
300 seconds.
