# FotoArchief v0.9.48

## Nederlands

### Wijzigingen in deze versie

- Geeft een concrete taakfout voor nog niet gescande primaire bestanden en hercontroleert bestaande `unscanned` originelen wanneer ClamAV actief is.
- Verstuurt voor beeldanalyse en beeldembeddings alleen een opnieuw gecodeerde, metadata-vrije JPEG-afgeleide met maximaal 1024 pixels binnen de ingestelde limiet.
- Voorkomt dat stille itemfouten als een voltooide AI-taak worden gepresenteerd.

### Operatoracties
Automatische veilige hercontrole vereist `COMPOSE_PROFILES=clamav`, `INGEST_SCANNER=clamav` en `CLAMAV_HOST=clamav` in de private runtimeconfiguratie, gevolgd door opnieuw aanmaken/starten van de deployment. Zonder ClamAV stopt de taak veilig met een melding. Deze release wijzigt geen Compose-template of environmenttemplate.

### Bewijs en grenzen
Deze toelichting is achteraf gebaseerd op de commits van deze tag en de gekoppelde PR's; er zijn voor deze aanvulling geen oude tests opnieuw uitgevoerd. Dit blijft een testrelease, geen productiecertificering. Bron: [helmerzNL/FotoArchief#11](https://github.com/helmerzNL/FotoArchief/pull/11). [Code van deze release / vergelijking](https://github.com/helmerzNL/FotoArchief/compare/v0.9.47...v0.9.48).

## English

### Changes in this version

- Reports an explicit job error for unscanned primary files and rescans existing `unscanned` originals when ClamAV is active.
- Sends only a re-encoded, metadata-free JPEG derivative for image analysis and image embeddings, capped at 1024 pixels within the configured limit.
- Prevents silent item failures from being presented as a completed AI job.

### Operator actions
Automatic safe rescanning requires `COMPOSE_PROFILES=clamav`, `INGEST_SCANNER=clamav` and `CLAMAV_HOST=clamav` in private runtime configuration, followed by recreating/starting the deployment. Without ClamAV, the job fails safely with a message. This release changes no Compose or environment template.

### Evidence and limitations
This retrospective description is based on this tag's commits and the linked PRs; historical tests were not rerun for this update. This remains a test release, not production certification. ## English

Test release containing readable PHP with locked production dependencies,
a Compose deployment archive and the Docker image accepted by this
workflow. This is not a production-readiness certification.

Download IMAGE.txt and IMAGE-DIGEST.txt for the immutable version tag and
digest. IMAGE-LATEST.txt references the rolling :latest tag, which is
updated to the same image by every successful highest SemVer release. Prefer
the version tag or digest for reproducible deployments. Alternatively,
load fotoarchief-docker.tar.gz with docker load and use the APP_IMAGE value
from IMAGE-LOCAL.txt; no registry credentials are required. The PHP host
requires PHP 8.5, PostgreSQL, the required extensions and cron/workers.
Set its document root to public/. Composer is not needed on the host.

Operator changes: set APP_IMAGE to the supplied tag or digest. Keep
DB_PASSWORD unchanged for existing volumes. Preserve app-storage and
postgres-data. The HTTP mapping remains
${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080. Packaging
introduces no new mandatory environment variables. Before upgrading,
create a verified backup and consult the operational documentation.
The application file limit is 104857600 bytes; every proxy must allow at
least 115343360 bytes per request and the configured request duration of
300 seconds.
