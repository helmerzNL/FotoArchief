## English

### Changes in this version

- Twenty additions: installation diagnostics, optional ClamAV acceptance, proxy/passkey checks, safe upgrade helper, Komodo update guidance, S3 acceptance, encrypted backup copy and operational alerts.
- AI capability and privacy controls, model contracts, local/external provider adapters and queued image analysis.
- Human review of AI suggestions, embedding index, staff and public semantic search, search-quality checks and expanded release packaging.

### Operator actions
Enable external services only after configuration and consent; an adapter or acceptance facility does not prove a working live provider, S3 destination or Komodo installation. Use the upgrade helper with a verified backup and preserve private storage and keys. Consult the linked change description and version-specific operational documentation for opt-in configuration.

Test release: readable PHP with locked production dependencies, Compose
deployment archive and the Docker image accepted by this workflow.
This is not a production-readiness certification.

Download IMAGE.txt/IMAGE-DIGEST.txt for the registry tag and immutable digest.
Alternatively load fotoarchief-docker.tar.gz with docker load and use the
APP_IMAGE value from IMAGE-LOCAL.txt (no registry credentials required).
The PHP host needs PHP 8.5, PostgreSQL, required extensions and cron/workers;
set its document root to public/. Composer is not needed on the host.

Operator changes: set APP_IMAGE to the supplied tag/digest. Keep DB_PASSWORD
unchanged for existing volumes. Preserve app-storage and postgres-data.
The HTTP mapping remains ${APP_BIND_ADDRESS:-127.0.0.1}:${APP_HTTP_PORT:-8080}:8080.
No new mandatory environment variables are introduced by packaging.
Before upgrading, create a verified backup and consult the operational docs.
The application file limit is 104857600 bytes; any proxy must allow at least
115343360 bytes per request and the configured 300-second request duration.
